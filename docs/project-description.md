# Super-Strategy Service (SSS): сервис торговой стратегии
---
## Что это за проект?
Проект представляет собой микросервисное приложение
по предоставлению рекомендаций на основе реальных или исторических
данных о рынке ценных бумаг. На основе предоставленной информации
через внешнюю платформу этот сервис выдает рекомендации по стратегии
торговли ценными бумагами через собственный алгоритм анализа.
---
## Зачем это нужно?
Сервис предоставляет помощь в анализе текущей ситуации на рынке ценных
бумаг как опытным, так и начинающим трейдерам. Рекомендации позволяют 
более точно сформировать финальное решение о покупке той или иной бумаги.
---
## Какую цель преследует проект? 
В данный момент цель проекта состоит в _разработке отказоустойчивого микросервиса 
по автоматизированному анализу входящего потока данных для торговли и формировании
рекомендаций на их основе._
---
## Какие задачи проект имеет на данный момент?
1. Релизация проверки состояния сервиса.
2. Интеграция с защищенным брокером сообщений.
3. Разработка алгоритма анализа и формирования рекомендаций.
4. Проектирование грамотной, расширяемой, поддерживаемой архитектуры проекта.
---
## Что будет в конечном итоге?
В конце разработки проекта подразумевается, что данный микросервис сможет корректно
работать с любым объемом данных, стабильно функционировать в форс-мажорных ситуациях, 
а алгоритм анализа и формирования стратегии будет помогать конечному пользователю выходить на положительную прибыль.
---
## А какие у проекта границы?
В зону ответственности проекта входит:
1. Парсинг и валидация входящих JSON-сообщений формата платформы.
2. Вычисление и формирование рекомендаций.
3. Реализация диагностического энд-поинта.
4. Корректная обработка ошибок в форс-мажорных ситуациях.

За пределами сервиса остаются:
1. Прямой доступ к реальным биржевым шлюзам и поставщикам котировок.
2. Исполнение сделок, учет баланса виртуального портфеля и комиссий.

С кем сервис держит контакт:
1. Платформа-агрегатор виртуальных сделок: центральный узел координации виртуальной биржи.
2. Брокер сообщений Kafka: единая шина взаимодействия.
---
## Как именно сервис взаимодействует со внешними системами?
В данный момент конкретный принцип взаимодействия микросервиса со внешними системами
находится в разработке, как и более конкретный список внешних систем.
---
## Что внутри?
Конкретные решения пока в разработке, до окончания проекта все может меняться.
```
controllers: Здесь лежат контроллеры, отвечающие за соединение со внешней платформой-агрегатором.
dto: Здесь находятся Data Transfer Objects в формате record-классов.
services: Планируется, что будут находиться все, что отвечает за обработку данных.
database: Планируется, что здесь будут находиться контракты общения с базой данных сервиса.
dev: Здесь будет находится все, о чем пока не принято конечное решение о внедрении.
```

## Какой у проекта технический стек?
- Язык программирования: Java 25
- Вспомогательные фреймворки: Spring Boot + Spring Web
- Сборщик: Gradle
- Брокер сообщений: Kafka
- Контейнеризация: Docker
- Система контроля версий и VCS-хостинг: Git + GitHub
- Система управления задачами: Github Projects
- Среда разработки: IntelliJ Idea Ultimate
- База данных: PostgreSQL

Вышеописанный технический стек предоставляет возможность комфортной разработки проекта
на всех его этапах: начиная от планирования, заканчивая реализацией. Выбранные инструменты
являются современными решениями, применяемыми повсеместно. Также они обеспечивают хорошую
совместимость со всеми современными платформами.
